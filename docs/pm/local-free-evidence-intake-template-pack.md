# Local-free evidence intake template pack

Purpose: prepare the human/external evidence channels that cannot be generated by local-free automation: license/legal, human UX, customer shadow, and external benchmark receipts.

This packet is **non-promoting**. It does not create legal approval, human observation, customer evidence, or benchmark receipt. It defines the minimum valid evidence so those blockers can be closed without rework.

## Evidence channels covered

1. License/legal approval
2. Human new-user UX observation
3. Customer shadow evidence
4. External benchmark terminal receipts

## Channel A — License/legal approval

Authoritative artifacts:

- `implementation/phase1/release/support_bundle/license_status.json`
- `implementation/phase1/release_evidence/productization/license_status_closure_report.json`
- `implementation/phase1/release_evidence/productization/license_status_intake_packet.json`

Minimum required fields:

- `status`: active, approved, or valid
- `tier`: paid-pilot or limited-commercial
- `license_id`
- `issuer_or_approver`
- `approver_role`
- `approval_ref`
- `approved_at_utc`
- `evidence_ref`
- `product_scope`
- `expires_at_utc` or explicit `perpetual=true`

Required product scope entries:

- `review-assist`
- `specified-structure-families`
- `specified-workflows`
- `engine-and-reviewer-evidence-package`

Evidence reference must not be:

- the license status JSON itself;
- docs template path;
- generated PM/license/readiness gate artifact;
- placeholder string such as `OWNER_INPUT_REQUIRED` or `LICENSE-ID`.

## Channel B — Human new-user UX observation

Authoritative artifacts:

- `implementation/phase1/release_evidence/productization/ux_new_user_observation.json`
- `implementation/phase1/release_evidence/productization/ux_new_user_observation_report.json`
- `implementation/phase1/release_evidence/productization/ux_new_user_observation_intake_packet.json`

Minimum required fields:

- stable anonymized participant reference;
- participant role: new_user, first_time_user, or pilot_user;
- `new_to_product=true`;
- human observer or UX research owner;
- start/completion timestamps;
- completion within 30 minutes;
- observed workflow steps;
- evidence reference separate from generated gate artifact;
- approval decision accepted/pass/signed/approved_for_release.

Required workflow steps:

1. Import
2. Model Health
3. Analysis Setup
4. Run & Monitor
5. Compare & Report

Disallowed substitutes:

- automated browser smoke;
- Playwright-only evidence;
- generated UX gate artifact as evidence_ref;
- participant who already knows the product.

## Channel C — Customer shadow evidence

Authoritative artifacts:

- `implementation/phase1/customer_shadow_evidence_status.json`
- `implementation/phase1/customer_shadow_evidence.schema.json`
- `implementation/phase1/customer_shadow_evidence/`

Minimum required posture:

- raw customer data retained by customer;
- redistribution allowed is false;
- derived metadata only in repository;
- completed-project shadow case;
- reviewer decision recorded;
- evidence row validates against schema.

Minimum target:

- completed customer shadow cases: `3/3`.

Recommended fields:

- `shadow_case_id`
- `customer_ref_anonymized`
- `project_family`
- `structure_family`
- `model_source_type`
- `raw_data_retained_by_customer=true`
- `redistribution_allowed=false`
- `derived_metrics_ref`
- `reviewer_decision`
- `reviewed_at_utc`
- `evidence_ref`
- `claim_boundary`

## Channel D — External benchmark terminal receipts

Authoritative artifacts:

- `implementation/phase1/release/external_benchmark_submission_readiness.json`
- `implementation/phase1/release_evidence/productization/external_benchmark_submission_updates.json`

Required benchmark lanes:

1. `hardest_external_10case`
2. `tpu_hffb`
3. `peer_spd_hinge`
4. `korean_public_structures`

Minimum receipt fields:

- `work_item_id`
- `submission_id`
- `submitted_at_utc`
- `last_checked_at_utc`
- `receipt_url` or retrievable evidence reference
- `receipt_status`
- `closure_evidence_status`
- `owner_action`
- `claim_boundary`

Disallowed substitutes:

- dry-run evidence as terminal receipt;
- local-only benchmark run as external receipt;
- reused stale update without fresh receipt metadata.

## Recommended closure order

1. License approval, because it gates paid-pilot and release security.
2. UX observation, because it gates PM release and Developer Preview.
3. Customer shadow 3/3, because it gates paid pilot and commercial credibility.
4. External benchmark 4/4, because it gates independent solver/commercial claim.

## Acceptance criteria

This evidence intake track is closed only when:

- license closure report passes;
- UX observation report passes;
- customer shadow status reports at least 3 completed shadow cases;
- external benchmark terminal receipts are attached for all four lanes;
- product readiness snapshot no longer reports these blockers.

## Claim boundary

Until evidence is attached and validated, the correct claim is:

> Intake paths and validation criteria are prepared, but external, human, legal, and customer evidence remain owner-input blockers.
