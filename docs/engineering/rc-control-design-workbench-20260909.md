# Workbench review of experimental RC design alternatives

The Workbench runtime configuration accepts `rcControlDesignUrl`, a same-origin
URL for the original `experimental-rc-control-design-comparison.v1` report.
Optional `jobAuthorization` credentials are requested only after origin checking,
kept in memory and supplied to report/artifact reads. Cookies remain available.
Redirects, invalid artifact paths, unsupported types and actual streamed byte
limits fail closed. The 64 MiB individual result limit is unchanged; all listed
artifacts together must fit a 256 MiB input budget and the report fits 2 MiB.

A dedicated worker validates alternatives serially and returns the compact
comparison and canonical models. It checks original byte hashes, Python JSON
self hashes without changing numeric tokens, request identity, candidate model
changes, member quantity arithmetic and common prices. Passing rows also require
stored fresh full-path verification, the original control request, native
checkpoint/state-parent bindings and every accepted target/fiber identity.
Response/material maxima are recomputed from the complete retained history,
then checked against each requested terminal and history screen. Failed rows
retain their quantities and known/unknown execution costs without becoming
selectable. All original invocation started/outcome records remain bound.

The panel compares physical and price differences against the baseline. It
starts with the producer's lowest declared estimate among verified alternatives
passing every screen. Users can select another eligible alternative and inspect
its canonical section dimensions, exact model/result/price identities and phase
costs. Missing prices or failed screens block selection. Selecting a candidate
preserves its original report/control-path identity and does not submit a solve.
Each original artifact and the complete comparison can be downloaded; downloads
are fetched again and checked against the verified original reference. A changed
download, worker error, cancellation or navigation retires the worker and removes
physical values and selection. Large histories remain outside React, though
whole JSON parsing and transient allocations still occur inside the worker.

The stored verification report is a producer statement. Browser checks do not
execute equilibrium or constitutive laws, recompute binary solver state hashes,
authenticate source or provide independent validation, a verified price quote,
design-code compliance or release approval. The permissive synthetic example
can pass screens even near complete concrete tensile damage; the screen result
must not be interpreted as a safe design recommendation.

The portable fixture is an actual three-target reversal study with two separate
original analyses, two fresh verifications and one invalid alternative retained
in the denominator. Explicitly marked decision-only fixtures remove prices,
tighten a terminal limit or inject an unknown verification failure using retained
physical bytes; they are not additional numerical observations.

Initial TypeScript checking rejected newer string/array conveniences under the
repository target; compatible expressions replaced them. The first complete
29-test selection had five failures: the new consumer compared the enriched API
configuration to the smaller request configuration, a mutation fixture assumed
a decimal token instead of scientific notation, and three browser checks could
not reach a valid review. The consumer now verifies the exact enriched profile
and the fixture mutates a stable epoch-count field. All failures remain recorded.
