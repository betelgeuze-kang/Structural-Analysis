# Local RC result reuse and bounded material-price search

This additive **local research** path does not change the reference solver,
convergence tolerances, existing exhaustive comparison, or acceptance authority.
It requires the RC direct-control work in PR #439. It is not a stable public,
GPU, multi-user, or persistent-storage interface.

## Reuse boundary

`RCControlResultSession` retains only original bytes generated by its own
virgin-state analysis **and fresh full reference verification**. A failed result,
failed verification, or unknown numerical work is never admitted. No file import,
pickle, external receipt registration, disk-cache loading, or cross-process reuse
is implemented. The first slice is intentionally process-local; integrating the
existing durable store and authenticated service is separate work.

Keys bind the full detached model including provenance, complete request (including
constant preload, target order and solver settings), source-revision label, package
source/schema fingerprint, interpreter/dependency versions and thread settings.
The source label is not an attestation. A package/runtime change rejects the
session; create a new session rather than promoting an old result to new code.
The trusted caller owns each session. `scope_id` must match but is **not** a token,
network authentication or a multi-tenant security boundary.

An entry consists of immutable original bytes. Every hit checks its in-memory
integrity and writes byte-identical originals to a new exclusive output directory.
Returned report dictionaries do not mutate retained entries. The LRU defaults to
32 entries / 64 MiB; an oversized valid result still completes but is not cached.
Only retained snapshot bytes are bounded, not total solver peak RSS. The session
serializes concurrent calls; candidate-level parallel execution is not added.

Prices and supported upper-limit screens do not enter the physics key. Repricing
and rescreening reuse the existing response extrema/quantities. Changing loads,
materials, section dimensions, targets, solver settings or source provenance
requires a miss. A new requested physical observable is not inferred from these
stored extrema. `fresh=True` explicitly bypasses reuse and performs a new complete
analysis/replay. The original scientific `compare_rc_control_designs` entry point
always executes fresh paths and never shares this session.

A hit reports `verified_original_reused`, zero new numerical work, the original
work separately, and `fresh_reference_verification_this_call=false`. Its original
verification bytes retain their historical claims; they are not a new independent
execution. No speed ratio, design approval, physical-validation credit or confirmed
currency saving is granted by a hit. Current call wall/CPU time includes context
checks and output writes except the final report write.

## Finite-pool cost bound, not exhaustive response coverage

`run_rc_control_cost_search` runs **one** declared candidate order. It does not run
a second strategy or exhaustive oracle. The baseline, all physical alternatives,
quantities, common prices and order are prepared before numerical work. The existing
one-to-sixteen alternative scope is retained. The baseline is scheduled first.
An optional full candidate-ID permutation can supply a predeclared ranking; an AI
prediction can never remove a cheaper candidate from the verification obligation.

Let a fully verified feasible candidate have estimate C*. Every strictly cheaper
candidate must have a **verified failure of a requested screen**, or be evaluated
and replace the incumbent, before a finite-pool minimum is confirmed. An unresolved
cheaper candidate, numerical failure, unknown result or exhausted budget leaves the
minimum unknown. An unverified candidate with cost >= C* cannot improve price, but
its physical response remains explicitly unknown. Equal-cost alternatives may remain
unverified: this proves the minimum price, not all tied winners or a preferred tie.
Zero prices/ties are valid. Comparisons use exact ordering of stored finite estimates,
not tolerance-expanded prices. All candidates must share currency, quantity scope
and price-table identity. Physical limits are caller-declared research screens.

The report separately states `response_coverage_complete` and
`pool_minimum_feasible_estimate`. It does NOT loosen or reuse the existing exhaustive
`candidate_cost_optimality_audit` contract. A finite declared-pool conclusion is not
a global design optimum, a physical safety approval, or a construction quotation.

`max_new_model_analyses` is 0..17 and counts new model evaluations including baseline.
Each such evaluation includes the original analysis and its fresh full replay;
recorded core calls, Newton iterations, linear solves and failures remain separate.
A valid hit costs no new-model budget. Known numerical failure is unknown feasibility;
unknown work stops scheduling. All unrequested candidates stay in the denominator.

## Use

Existing v3 experiment files supply candidates, explicit prices, terminal (optional),
full-history and material-history screens. Existing v1/v2 control requests are reused.
For a single local process with multiple price/screen scenarios:

```sh
PYTHONPATH=src python -m structural_analysis.benchmark.rc_control_local_search_cli \
  --model examples/public_rc_fiber_frame_cantilever.json \
  --request /path/to/control-request.json \
  --experiment /path/to/prices-and-limits-a.json \
  --experiment /path/to/prices-and-limits-b.json \
  --source-revision <exact-reviewed-source-sha> \
  --max-new-model-analyses 4 \
  --output /new/local-research-output
```

The budget is shared across scenarios, not reset for each price table. Output
folders must be new. Exit 0 means all requested local searches have confirmed their
scoped pool minimum; 2 means incomplete selection/coverage conditions or unknown
work; 1 means invalid input/output. This does not imply engineering approval. Model
JSON rejects duplicate keys before the canonical loader. A new process starts cold.

For programmatic use, construct `RCControlResultSession` with a source revision and
ownership label; call `evaluate` repeatedly for one model or pass it to
`run_rc_control_cost_search`. API-level cache admission/import is deliberately absent.

## Verification and explicit remaining work

Focused tests combine exhaustive arithmetic completions of three-state candidate
outcomes with real small RC solves: 600 kN constant preload, three reversing
lateral targets, physical section alternatives, fresh replay, byte-preserved cached
originals, repricing, rescreening, budget limits, concurrent duplicate requests,
LRU eviction, bad context, source changes, corruption and failure injection.
Fault-injection arithmetic tests are not experiments. Run:

```sh
PYTHONPATH=src python -m pytest -q tests/test_rc_control_local_research.py
```

The extracted single-model helper preserves the original comparison's numerical
calls and verification predicates. Scientific comparison remains fresh. In the
local authored pool, reference/full replay for baseline plus three alternatives
costs 32 core calls; the price-bounded local search uses 16 and selects the same
scoped minimum. Repricing a warm two-model session uses zero new core calls. These
are call-count observations, not a measured general speedup, AMD result, market
price or independent validation. The local test environment is a partial checkout
built from the base CI wheel plus changes; full hosted CI remains the merge gate.

Persistent authenticated storage, browser report ingestion, durable scheduling,
AMD hardware qualification, resource parallelism and improved learned proposals
are not implemented by this slice. No protected receipts, benchmark values,
scientific tolerance or required full-suite job is weakened.
