# Offline line-search alpha decision screen

This is a development-only feasibility screen. It reads the original, completed
pooled RC runtime packet with inventory SHA-256
`a2c9b9d141db3c4718d3d69e02590a82d91282ed1994bce2a11c8e39c20b8409`
and numerical source `80f9ff404dfa15f7048c21d673f348155f90d965`.
The packet contains 15 authored training cases in five whole geometry/history
groups (A through E), with two ridges and three repetitions per case. The two
reserved cases and all protected project state are outside this screen. An
initial read-only scout had already seen a few nonunit alpha trials before this
protocol was written. This is therefore a source-bound diagnostic, not a blind
test or an independent held-out evaluation.

The script authenticates consumed original files against the packet inventory,
the fold report and path hashes, and the declared source/request. It checks all
90 secant paths and their original step bytes. The one ridge-10,000,
repetition-zero path for each case supplies unique training/evaluation rows;
the other five paths per case check repeat identity without adding duplicate
training examples. A failed, retried, missing, or unknown-work invocation remains
in the report and cannot supply an eligible label. If the complete roster or
trial-level history is unavailable, the screen fails closed.

For each authenticated primary Newton line search, the input features are fixed
before fitting: iteration index, log10 of its already assembled relative
residual, log10 of the already computed Newton-increment infinity norm, the
requested target increment from the accepted prefix, and the preceding line
search's selected-alpha index (`-1` when absent). Case/group identity, current
or future accepted answer, trial residuals, and execution work are never model
features. The label is the zero-based index of the **first** alpha whose original
trial reduced the residual, from the unchanged thirteen-factor binary grid
`1, 1/2, ..., 1/4096`. A complete trial history with no accepted alpha has a
null label and is not silently converted to a negative example.

The fixed offline baseline uses each other whole group's rows, standardizes
features on those training rows only, and predicts skipping alpha `1` only when
the held row lies inside every training feature range and its three nearest
training rows all had a first accepted index of at least one. Otherwise it
predicts the unchanged alpha `1` start. This is an intentionally conservative
binary screen, not a trained solver policy. For a held row whose original first
accepted index is at least one, predicting a one-position skip could omit one
recorded failed trial while reaching the same originally accepted alpha. If the
original index is zero, the proposed skip has an unobserved numerical outcome:
it is counted as a false skip, never as a saving. No new trajectory, wall time,
or solver call is inferred from this replay calculation.

Before considering a separate online experiment, this screen would need logged
positive labels in at least three of five held groups, safe predicted skips in
at least three held groups, and zero false skips. Passing those descriptive
conditions would still require a separately frozen optional solver hook, full
own-history paths, secant with deterministic assembly reuse as baseline,
unchanged equilibrium/commit/full-history checks, and complete feature,
inference, retry, recovery, verification, and training cost accounting. No
online hook or public default changes are part of this slice.

The complete source-bound output is generated by
`scripts/screen_rc_line_search_alpha.py`. Counts of line-search trial evaluations
are work proxies; this source packet does not time individual alpha trials.
Path, solver, preparation, and historical training intervals overlap or have
different boundaries, and this screen does not combine them into a net-speed
estimate.
