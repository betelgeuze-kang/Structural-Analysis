# RC held-out runtime software contract

Issue [#480](https://github.com/betelgeuze-kang/Structural-Analysis/issues/480) remains open. The grouped development selector executes training cases only. Its current selected strategy is secant, so no policy or cohort is eligible for held-out execution. This change adds an execution contract; it does not run the two reserved cases or claim learned speedup.

`declare_heldout_runtime` requires an exact development selection result with a frozen learned policy. It checks all supplied train, validation and holdout cases through the existing conservative split preflight, then binds each case's project, geometry, load-history, model, request, original-record hash, lineage group and rights-review hash. Source record roles and rights decisions are supplied reviewed inputs. The function does not establish the legal authority or authenticity of those external receipts. A source reviewer must verify those records before any real cohort is admitted. The declaration fixes the entire evaluation roster, three or six rotated arm orders, zero warmups, tolerances, arithmetic, failure denominator and decision rule before execution.

`run_heldout_slot` executes one declared case and repetition from its own genesis. Call each slot in a separate fresh process, from the exact clean committed source, with output directories named `slot-0000`, `slot-0001`, and so on. It runs reference, secant, learned proposal and fresh reference through the existing full-path benchmark, retaining the benchmark's original path files, failed attempts, fallbacks, full response-history comparison and solver work. A raised slot leaves a started and terminal unknown-work receipt. The policy, input hashes, source revision and schedule are rechecked before any numerical execution.

`audit_heldout_receipts` checks the stored comparison and each original path hash, input and policy bindings, score, and enclosing benchmark costs. It keeps missing, failed, incomplete, unknown-work and fallback-only slots in the declared denominator. Only actual seeded proposal entries count as learned proposals. Per-case paired path ratios are diagnostic; a case mean is absent unless every declared repetition qualifies. Repeated slots from one process are rejected.

The ledger records wall and CPU for policy loading, preflight, gate where used, benchmark and the enclosing slot. It leaves process startup, historical label generation, training and selection fits, internal capture, inference, solver, recovery, report I/O and separate audit scopes explicitly unknown or separately nested. The enclosing timers must not be added to their component timers. Because original rights and full lifecycle costs are not independently audited here, total evaluation cost, training-cost reuse and break-even remain unknown, and the result retains secant. A later issue #480 slice must fill and audit those fields before a net-benefit decision.

Focused contract tests use generated temporary synthetic cases. They do not execute the grouped campaign's reserved validation or holdout cases and are not independent physical validation.
