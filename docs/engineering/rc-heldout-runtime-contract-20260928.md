# RC held-out runtime software contract

Issue [#480](https://github.com/betelgeuze-kang/Structural-Analysis/issues/480) remains open. The grouped development selector executes training cases only. Its current selected strategy is secant, so no policy or cohort is eligible for held-out execution. This change adds an execution contract; it does not run the two reserved cases or claim learned speedup.

`declare_heldout_runtime` requires an exact development selection result with a frozen learned policy. It checks all supplied train, validation and holdout cases through the existing conservative split preflight, then binds each case's project, geometry, load-history, model, request, original-record hash, lineage group and rights-review hash. Source record roles and rights decisions are supplied reviewed inputs. The function does not establish the legal authority or authenticity of those external receipts. A source reviewer must verify those records before any real cohort is admitted. The declaration fixes the entire evaluation roster, three or six rotated arm orders, zero warmups, tolerances, arithmetic, failure denominator and decision rule before execution.

`run_heldout_slot` executes one declared case and repetition from its own genesis. Call each slot in a separate fresh process, from the exact clean committed source, with output directories named `slot-0000`, `slot-0001`, and so on. A second slot in the same process is rejected before it can create an output directory. It runs reference, secant, learned proposal and fresh reference through the existing full-path benchmark, retaining the benchmark's original path files, failed attempts, fallbacks, full response-history comparison and solver work. A raised slot leaves a started and terminal unknown-work receipt. The policy, input hashes, source revision and schedule are rechecked before any numerical execution.

`audit_heldout_receipts` checks the stored comparison, input and policy bindings, score, and enclosing benchmark costs. A slot inventory binds the bytes of every original file present when its outcome was written, including per-step attempts and partial files from a raised slot. The audit also recomputes the three full response-history comparisons across the four paths and the fresh-reference repeat from the original path files, without a new solver run. The inventory detects missing, added, or changed files after slot completion; it does not independently authenticate the producer. Missing, failed, incomplete, unknown-work and fallback-only slots stay in the declared denominator. Only proposals reaching a seeded numerical invocation count as actual learned proposals. Per-case paired path ratios are diagnostic; a case mean is absent unless every declared repetition qualifies. Repeated slots from one process are rejected.

The ledger records wall and CPU for policy loading, preflight, gate where used, benchmark, receipt inventory and the enclosing slot. The audit reports its own separate read/hash/recheck interval. Process startup, historical label generation, training and selection fits, internal capture, inference, solver, recovery and remaining report I/O remain explicitly unknown or separately nested. The enclosing slot interval includes inventory creation and excludes its final outcome write; the audit interval excludes any later summary write. Nested timers must not be added. Because original rights and full lifecycle costs are not independently audited here, total evaluation cost, training-cost reuse and break-even remain unknown, and the result retains secant. A later issue #480 slice must fill and audit those fields before a net-benefit decision.

Focused contract tests use generated temporary synthetic cases. They do not execute the grouped campaign's reserved validation or holdout cases and are not independent physical validation.
