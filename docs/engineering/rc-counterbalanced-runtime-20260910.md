## Repetition contract

`repetitions=1` retains the existing plan/result v1, fixed order and per-case
fit behavior. `repetitions=3` or `6` emits plan/result v2 and repeats every
withheld training case using these cyclic arm orders:

1. Reference, secant, learned proposal.
2. Secant, learned proposal, reference.
3. Learned proposal, reference, secant.

Six repetitions repeat that cycle. Each arm occupies each position equally.
Every repetition ends with another fresh reference path for complete-history
comparison. No warmup is silently omitted. The outer order is ridge, withheld
training case, repetition. This counterbalances within-case arm position; it
does not randomize case order or establish isolated hardware conditions.

Each ridge/case pair is fitted **once** on the other training cases and its
policy remains frozen across repetitions. Repetition indices, actual arm order,
fit index, policy identity, original path records, decisions and costs remain
linked. The conservative core-call reservation multiplies by repetition count;
the fit reservation does not. One possible final all-training refit remains
reserved under the existing selection rule. No validation/holdout case executes
and no new training label is generated by this selector.

The score is the equal-case mean of within-case mean proposal/secant path-time
ratios. Per-case reports retain every ratio, requested/valid repeat counts, mean,
minimum, maximum and sample standard deviation. Repeating a case does not create
independent physical cases. A failed comparison leaves a null ratio, invalidates
that case's aggregate and makes the candidate ineligible; it is not dropped.
Unknown execution work stops the study before the next repetition. The unchanged
improvement threshold and requirement for actual learned proposals still apply.
Passing them does not authorize promotion or independent-performance claims.

When static model abstention is enabled, each repetition recomputes the original
one-way rejection check and charges gate computation plus record writing to the
proposal score. Only a proved rejection skips material capture and inference;
it still uses secant where available, otherwise the reference initial value.
A static non-rejection cannot authorize a proposal and retains the full dynamic
checks. Full paths, reference tolerances, accepted-result authority, original
outputs and fresh comparisons remain unchanged.
