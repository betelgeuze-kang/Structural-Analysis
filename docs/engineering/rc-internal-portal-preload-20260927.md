# Internal two-base portal: bounded reversals and constant preload

The internal dense corotational fiber-frame solver now accepts an opt-in displacement target path with a bounded number of reversals. The default path remains strictly monotone. It checks all targets before the first solve, including the checkpoint's actual control coordinate, duplicate targets, the 255-target limit, and the reversal budget. A failed step leaves the last accepted checkpoint unchanged. The budget applies only to the supplied path suffix; a checkpoint by itself does not attest to reversals in an earlier prefix.

An optional `constant_external_loads` channel on the internal problem separates fixed nodal forces from the proportional reference load. Dense assembly uses `F_ext = F_constant + lambda * F_reference + F_member_equivalent`; the constant term is omitted from `dR/dlambda` and included in support reactions. Nonempty constant loads change the problem hash and therefore bind checkpoint restart to the load definition. Empty-channel hashes remain unchanged. Native sparse assembly, typed portal/connected profiles, and the six-DOF execution-topology conversion reject a nonempty constant channel until they represent it in their own contracts.

The genesis checkpoint has zero displacement and load factor; it is not an equilibrated state under a nonzero constant load. The internal test first commits a load-control solve at `lambda = 0`, then runs cyclic displacement control from that accepted checkpoint. This is a one-step application of the full constant load, not a staged preload history. The test's two-base portal is a small elastic numerical exemplar (2 m by 2 m, 20 mm by 20 mm members, 0.02 kN downward force at each roof node). It checks the stored response and reaction balance, the load-factor Jacobian column against finite differences, exact serialized restart, repeated cyclic results, and failed-step rollback.

The public RC direct-control compiler still admits only a one-support serial chain, and the public planar profile still rejects direct displacement control. The new internal dense capability is neither sparse performance evidence nor independent physical validation, and it does not establish a useful recovery or learned-speed policy. The [original portal admission packet](rc-portal-recovery-admission-20260921.md) remains an unchanged record of the public compiler rejection.

## Original-model 25 kN preflight

One bounded internal preflight used the preserved 4 m by 3 m, three-member model and the 20 mm request. Its original model SHA-256 is `6f8eec155f5fcf2f9ae942c021a8692e79ae1efd0d1b98342f8aea0b642d0ed6`; its request SHA-256 is `e0cbc4995e2c98f4a30a0902ac321b4a0e66a9baa61ed20a88e5e73809df627e`. The public compiler still returned `rc_fiber_frame_support_count_unsupported`. For the internal experiment, each of the original three element type tags was changed from the fixed-chord RC element to the corotational RC element; the internal portal compiler created the problem, and constant vertical loads of -25 kN were bound to both roof nodes. The original two fixed bases, RC1 section (0.4 m by 0.6 m, 12 concrete layers), and 150 kN horizontal reference load were retained. The formulation change means this is not an exact run of the original public model.

The one-step `lambda = 0` preload committed in 2 linear solves and 6 dense assemblies. The subsequent -10, -20 and +10 mm targets all committed in 14, 12 and 16 linear solves respectively, with 157 dense assemblies across the path. Two fresh process runs had identical numerical and work fields, checkpoint hashes, parent bindings, and final checkpoint serialization roundtrips; their path wall times were 7.144 and 7.084 seconds. These are two observations of one internal path, not a speed comparison. The largest free residual across accepted steps was about `1.01e-9` kN and the largest global force-balance remainder about `1.70e-10` kN. [Machine-readable preflight](rc-internal-portal-25kn-preflight-20260927.summary.json) retains the source hashes, work, timings, and accepted checkpoint hashes.

The original request enabled terminal polishing; the internal direct-control path does not expose that option. Its reference, secant, learned proposal, fixed/adaptive recovery, and fresh-verification arms have not been ported to this formulation. The 40/80 mm conditions and proposed 48-path comparison remain unexecuted. No independent physical validation or sparse speed result follows from this preflight.
