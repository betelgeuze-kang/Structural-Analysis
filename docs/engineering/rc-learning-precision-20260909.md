# Explicit retained arithmetic for RC learning generation and evaluation

The repeated deterministic secant observation passes all six full physical
comparisons for the two declared development geometries. This implementation
connects its arithmetic recipe to the existing train-only RC learning pipeline as
explicit `arithmetic_profile="retained-twofold-refinement.v1"`. It selects exact
rational strain, native twofold increments, retained coordinate-to-fiber material
trials, rational force/tangent accumulation and two retained terminal corrections.
Every case must already enable original terminal polishing before any labels or
output are produced. The original solver gates and comparison tolerances remain.

All static physical features still come from the original supported compiled
model with the public feature extractor's exact member/material type guards.
An experimental learning context then binds the selected problem contract and
explicit arithmetic recipe while preserving physical feature values and layout.
The general public feature extractor does not gain admission for experimental
section types. Training and evaluation compile the same declared recipe; proposal
contexts must bind the actual selected problem hash.

The opt-in policy uses an exact v2 schema carrying the full arithmetic manifest,
while ordinary policies retain their v1 schema and default wire fields. A policy
cannot enter a differently declared arithmetic context even if its other metadata
matches. Modified, missing or noncanonical arithmetic fields, including a floating
refinement limit, are rejected. The model-context hash, sample hashes and policy
hash bind the recipe. These are consistency checks, not source authentication.

Only the original accepted high coordinate component trains the existing
binary64 initial-guess predictor. Each sample also preserves the original absolute
low component and step-byte hash as provenance. No low component is presented as
learned or discarded from the authoritative solver state. Proposals remain finite
initial iterates; final Newton assembly, native commit and original recovery retain
both components under the selected solver profile.

Existing project/family/physical/geometry/history split screens run before label
collection under either profile. All preprocessing and weights use only train
rows; no evaluation response enters fitting. Generation, fitting, inference,
recovery, rejected attempts and full evaluation costs remain separately charged.
The policy is frozen before evaluation and decoded in a fresh interpreter in tests.

Initial focused checks pass 20 tests in 35.09 s. Broader learning/split, retained
terminal, rational assembly and quality-contract checks pass **83 in 56.97 s**,
including all eight split-alias rejection cases under the new profile. Tests
exercise actual four-case cyclic label generation/evaluation, provenance for every
label, train-only statistics, policy mismatch rejection, schema corruption, OOD
abstention and the unchanged public feature boundary. Ruff/diff checks pass.

Before a new complete observation, fresh baseline and candidate processes must
reproduce ordinary learning samples, policy bytes, original step files and native
histories exactly. A separate pilot then reuses the four original authored
training/validation/holdout models and all 242 targets with unchanged ridge `1e-6`
and OOD margin `0.1`. Source, inputs, profile and complete costs are frozen. Full
physical comparisons and original-record verification must pass before admitting
three fresh repetitions. A pilot timing alone cannot establish repeated learned
acceleration. Earlier failed/slower learned observations remain unchanged, and
independent project/physics evidence, public admission, hosted/full-suite acceptance
and the full roadmap remain open.
